# Sketch 001: PFOS Report Layout

## Design Question

在不改变 PFOS 现有计算引擎和底部设置区域的前提下，Dashboard 应采用一份连续阅读的报告，还是更强调立即行动的卡片式报告？

## How to View

打开 `.planning/sketches/001-pfos-report-layout/index.html`。

## Variants

- **A：结论优先 · 连续报告** — 严格按 01–06 阅读顺序，减少卡片切割感，适合完整阅读。
- **B：行动优先 · 决策卡片** — 保留 01–06 顺序，但将最紧急行动和关键风险做成更强的视觉锚点，适合快速扫读。

## What to Look For

- 打开页面后 10 秒内能否回答“我现在处于什么状态、何时缺钱、先做什么”。
- 今天／本周／本月三项行动是否足够突出且不制造焦虑。
- 90 天时间线和债务前三名是否在手机上易读。
- 01–06 的完整报告是否过长、过碎或信息重复。
- 底部“设置”和数据截止信息是否保持原有熟悉感。
